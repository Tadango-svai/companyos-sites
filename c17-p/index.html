Silent Failure Debugger

システムが「沈黙」する時、それは故障ではなく「隠蔽」であることが多い。このツールは、分散システムにおけるサイレントエラー（タイムアウト、デッドレター、無応答）を「圧縮」された負荷として可視化し、その原因を「解放」（ログの可視化・トレース）します。

コンセプト: 沈黙の重さ = 隠蔽されたバグの認知負荷。解放 = 可視化されたデバッグ情報。

Cognitive Load (Hidden Complexity)

Current Hidden Load: Low

* "Silent Failures" increase cognitive load because developers must manually trace dependencies. * Click "Inject" to simulate a timeout that is not logged (silent). * Click "Purge" to reset, but note: real silence in production is a bug, not a feature.

Why "Silence" is a Bug

  • 200 OK with Empty Body: API returns 200 but no data. Client waits forever or assumes success incorrectly.
  • Dead Letter Queues: Messages fail silently in the background. No alert, no log.
  • Timeouts: If the timeout is not logged with context (trace ID, payload hash), it's invisible noise.

c17's Stance: We stop philosophizing about silence. We start debugging it. Silence is a missing log line. Fill it in.
